# Контракт ИИ-агента — Кортекс организации

Этот репозиторий — **память организации**, а не документация о продукте.
Каждый `.md` с YAML-frontmatter в `GROUND/NEXUS/` — узел графа; рёбра выводятся
из полей детерминированно. Ваша работа здесь — поддерживать этот граф пригодным
для принятия управленческих решений и контроля бизнес-процессов: решение,
опирающееся на узел без источника, ничем не лучше решения без памяти.

Методология: PAF ([S1] https://productframework.ru/ops/main,
[S2] https://productframework.ru/ai_product_roles).

## 1. Что загрузить перед работой

| Файл | Зачем |
|---|---|
| `GROUND/config.yaml` | чья это организация, продукт, roster ролей, шаг PAF |
| `GROUND/NEXUS/_registry.yaml` | какие Нексусы существуют — **допустимые значения `nexus:`** |
| `GROUND/NEXUS/ops-model/principles.md` | принципы, по которым принимаются решения |
| `GROUND/NEXUS/ops-model/memory-protocol.md` | как писать в vault |
| `GROUND/NEXUS/ops-model/delegation-boundary.md` | что решаете вы, что решает человек |
| `VISION.md` | намерение организации: то, чем меряется граф |
| `ROADMAP/kr-epic-map.md` | хребет OKR: цели квартала |

Не уверены, что уже есть в памяти, — сначала `./scripts/cortex.sh report`,
потом действие. Дубликат узла хуже отсутствующего узла.

## 2. Пять запретов

1. **Не писать узел без `sources`.** Источник — документ, интервью, аналитика,
   эксперимент, решение встречи. «Логично предположить» источником не является.
   Нет источника — не создавайте узел, а зафиксируйте вопрос человеку.
2. **Не повышать `confidence` рассуждением.** CP растёт только вместе с новым
   источником в `sources`. Переписали формулировку красивее — CP не изменился.
3. **Не выдумывать идентификаторы.** `node_id`, на который ссылаетесь, обязан
   существовать; ключи задач (`ABC-123`) берутся из трекера, а не из головы.
   Висячее ребро роняет гейт.
4. **Не закрывать дыру правдоподобным содержимым.** Пустой раздел с честным
   «не измерено» — рабочее состояние памяти. Придуманная цифра — workslop,
   который потом невозможно отличить от факта.
5. **Не решать за человека.** Цель, приоритет, выбор гипотезы, повышение CP по
   спорному источнику — за человеком (см. `delegation-boundary.md`).

## 3. Как создать узел

1. Выберите Нексус: значение `nexus:` берётся **только** из `_registry.yaml`.
2. Возьмите шаблон: `GROUND/NEXUS/<нексус>/_template.md`.
3. Задайте `node_id`: ascii, нижний регистр, стабильный навсегда
   (`seg-smb-retail`, `f-billing-export`, `team-ivanov-ivan`). Переименование
   узла = потеря рёбер, поэтому имя выбирается один раз.
4. Заполните обязательные ключи: `nexus`, `node_id`, `node_type`, `kind`,
   `owner`, `confidence`, `sources`, `updated`, `ttl_days`, `ripeness`.
5. Проставьте рёбра полями (§4) — только на существующие узлы.
6. Тело: 3–8 строк. Один факт — один узел. Для допущений — пометка
   «⚠️ допущение (онбординг), требует валидации».
7. `./scripts/cortex.sh gate` — ноль ERROR.

### Значения, которые нельзя перепутать

| Ключ | Допустимо |
|---|---|
| `kind` | `normative` (методология, CP = трассируемость) · `empirical` (контекст организации, CP = доказательства) |
| `node_type` | `spine`, `operating-model`, `person`, `product`, `service`, `interface`, `platform`, `feature`, `value-proposition`, `need`, `segment`, `objective`, `key-result`, `epic`, `task`, `episode`, `risk`, `decision`, `entity`, `concept` |
| `ripeness` | `fresh` · `ripening` · `wilting` — **вычисляется**, не выбирается |
| `confidence` | 0.2–0.4 допущение · 0.5–0.7 подтверждено интервью · 0.8–1.0 данные/эксперимент |
| `ttl_days` | normative 365 · product/customer/market 90 · growth 60 · team 180 |

## 4. Рёбра пишутся полями, не текстом

| Поле | Ребро | Откуда → куда |
|---|---|---|
| `has_need` | HAS_NEED | segment → need |
| `addresses` | ADDRESSES | value-proposition → need |
| `realizes` | REALIZES | feature → value-proposition |
| `depends_on` | DEPENDS_ON | product → feature |
| `based_on` | BASED_ON | узел → узел-основание |
| `satisfies` | SATISFIES | узел → key-result |
| `serves` | SERVES | key-result → objective |
| `owner` / `owns_node` | OWNS | человек → узел |
| `reports_to`, `manages`, `collaborates_with` | org / social graph | person → person |

**Ось ценности организации:**

```
segment —has_need→ need ←addresses— value-proposition ←realizes— feature → product
```

Узел вне этой цепочки не достижим от хребта OKR: `./scripts/cortex.sh gaps`
покажет его сиротой. Связь, упомянутая только в тексте, графом не становится.

## 5. Обновление и свежесть

- Меняете содержание — обновляйте `updated` на сегодня.
- `ripeness` пересчитывается: `p = (сегодня − updated) / ttl_days`;
  `<0.5` fresh, `<1.0` ripening, `≥1.0` wilting.
- Узел `wilting` **верифицируют или понижают ему CP**. Продлевать дату без
  проверки источника запрещено: это подделка свежести.
- Новый источник противоречит узлу — не затирайте молча: обновите узел,
  сохраните оба источника и опишите в теле, что изменилось и почему.

## 6. Люди и владельцы

- Пока в `GROUND/NEXUS/team/` нет узлов-персон, `owner:` — роль PAF
  (`Product Engineer`, `Portfolio Manager`, `Growth Engineer`, `Product Ops`).
- Как только персона заведена, `owner:` — её имя («Иван Иванов»): движок
  сопоставляет первые два токена с `full_name` и выводит ребро OWNS.
  Неразрешённые владельцы движок складывает в очередь, это видно в `report`.
- Персональные данные в публичном репозитории не размещаются.

## 7. OKR и эпизоды

- Цели квартала живут **только** в `ROADMAP/kr-epic-map.md`. Узлы `objective` /
  `key-result` в `GROUND/NEXUS/okr/` генерирует движок (`./scripts/cortex.sh build`) —
  руками их не пишут и не правят.
- Эпизод встречи — файл в `GROUND/PULSE/summaries/` по формату
  `_template.md` (русские ключи `дата`, `участники`, `nexus_links`).
- Эпизод сам узлы не обновляет: решение из встречи попадает в память, только
  когда вы явно правите узел и добавляете эпизод в его `sources`.

## 8. Перед каждым коммитом

```bash
./scripts/cortex.sh gate      # ноль ERROR — обязательное условие
./scripts/cortex.sh report    # что стало с Context Ripeness
```

`WARN: пустой sources (MOC-заглушка)` у `_index.md` — это список ненаполненных
Нексусов, а не поломка. Он гаснет по мере онбординга.

## 9. Словарь: как называть вещи

PAF переопределяет термины, и память должна говорить на одном языке.

| Не писать | Писать | Почему |
|---|---|---|
| Беклог (накопительный список) | **Банч** | PAF упраздняет беклог [S1] |
| Product Manager как финальная роль | **Инженер продукта** | роль трансформируется [S1], [S2] |
| Приоритизация списка задач | **Скаутинг возможностей и угроз** | принцип 5 [S1] |
| Убытки как объект оптимизации | **Риски (энтропия)** | принцип 4 [S1] |
| T-shaped | **Comb-shaped** | эпоха ИИ [S2] |
| «Документация по продукту» | **Цифровой профиль (Нексус)** | документация исчезает [S2] |
| Скорость разработки как метрика | **mNSM / NPV / Confidence Point** | смена объектов измерения [S1] |

## 10. Когда остановиться и спросить

Спрашивайте человека, а не додумывайте, если:

- источник противоречит `VISION.md` или узлу с высоким CP;
- нужно повысить CP, а источник спорный (одно мнение, один разговор);
- появляется новый Нексус или меняется граница делегирования;
- эпизод содержит решение, которое меняет цель или приоритет квартала;
- данные, которые предстоит записать, персональные или коммерчески закрытые.

Вопрос без ответа — нормальный артефакт: положите его в тело узла разделом
«Открытые вопросы» с низким CP, а не в виде правдоподобного утверждения.
