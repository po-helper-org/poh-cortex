# Очередь проходила гейт молча, возраст очереди врал после клона

## Ситуация

Готовили общий Кортекс для трёх PO-агентов Hermes (GDS, Live, MRS) поверх реестра
`po-okr-registry`. Прогон сценария «три профиля, боты пишут в очередь» на одноразовой
копии показал: запись бота в каталог чужого профиля и запись без `captured_by` гейт
пропускает, а очередь с записью от 10.11 повестка называла «самой старой 0 дн.».

## Причина

- `run_gate` пропускал всё вне `NEXUS/` и `DECIDE/` до проверки провенанса — проверка
  зон сборщиков была объявлена в README и `agents.yaml`, но не исполнялась.
- `_intake_age` брал `st_mtime`, который сбрасывает каждый `git clone`, восстановление
  и перенос сервера.
- Срезы-образцы и вычисляемые поля зависят от даты: проверка CI «срезы пересобраны»
  краснеет со временем без правок памяти.

## Решение

- Гейт проверяет записи `_intake/` с frontmatter: чужая очередь — ERROR; нет
  `captured_by` — новая проверка `intake_provenance` (warn в шаблоне, error там, где
  пишут боты; решает человек в `SCHEMA/checks.yaml`).
- Возраст записи — по `date`, затем по дате в имени файла, затем по строкам `inbox.md`,
  и только потом по файлу.
- `cortex health [--json]` — числа для монитора: гейт, очередь, черновики, увядание
  по зонам, сироты, расхождения, отставшие срезы, `status` и `alerts`.
- `pack --all` удаляет срезы профилей, которых больше нет.

## Как проверить

`tests/acceptance.sh` — три новые проверки: «сборщик не кладёт запись в очередь чужого
профиля», «запись очереди без подписи видна в гейте», «возраст очереди считается по
дате записи». `tests/smoke.sh` — «здоровье считается». `bin/cortex health`.

## Чего не делать

Не давать ботам рабочую копию с правом записи в расчёте на гейт: `captured_by` пишет
сам автор записи, и гейт ловит нарушение только после записи. Писатель должен быть
один и подписывать запись сам (как сервис `poh-widget-okr` по ключу агента).
