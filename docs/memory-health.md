# Как понять, что память живая

Порядок действий — в [ONBOARDING.md](../ONBOARDING.md). Здесь только признаки,
по которым видно, что онбординг идёт правильно, а память не выродилась в
документацию. Каждый признак проверяется командой, а не ощущением.

## По ходу наполнения

| Стадия | Чем проверяется | Что должно быть видно |
|---|---|---|
| настройка | `cortex doctor` | список «не настроено» пустеет; пункты закрываются интервью, а не сами собой |
| первые узлы | `cortex gate` | ноль ERROR; предупреждения только про ненаполненные `_index` |
| наполнение Нексуса | `cortex report` | у Нексуса появились узлы, спелость перестала быть нулевой |
| связывание | `cortex gaps` | сирот становится меньше: знание привязано к целям, а не висит само по себе |
| приёмка | `cortex review` | очередь черновиков пустеет, а не растёт |
| цели квартала | `cortex gaps` | достижимость от хребта считается, то есть цели вообще заведены |

## Признаки живой памяти

| Признак | Чем смотреть |
|---|---|
| нет узлов без источника | `gate` |
| нет висячих рёбер | `gate` |
| вычисляемые поля не разошлись | `refresh --dry-run` → «всё актуально» |
| знание достижимо от целей | `gaps` |
| доля увядающего не растёт от квартала к кварталу | `report`, колонка «увяд» |
| очередь разбирается быстрее, чем наполняется | `agenda`, строка про очередь |
| у стыков между зонами есть владельцы | `seams` |
| расхождения находятся и закрываются источником | `conflicts` |

## Признаки мёртвой памяти

Их стоит знать наизусть: каждый выглядит как успех.

| Выглядит как | На самом деле |
|---|---|
| узлов много, у всех высокая ступень, источники одинаковые | уверенные выдумки: ступень ставилась по узлу, а не по артефакту |
| гейт зелёный, но `gaps` показывает почти всё сиротами | память есть, к решениям она не привязана |
| ни одного «не знаю» за весь онбординг | вопросы задавались формально |
| очередь `_intake` растёт неделями | поток собирается в никуда; либо разбирать, либо перестать собирать |
| `stale` неделями показывает одни и те же узлы | у знания нет владельца, и увядание ничьё |
| у всех узлов `change_rate: unknown` | срок годности не выводили, а проставили по умолчанию |
| после калибровки ничего не поменялось в правилах | калибровку провели ради отчёта |

## Что делать с увяданием

Протухший узел — **не ошибка и не долг**. Это сигнал, что знание пора
проверить. Два допустимых исхода:

1. **Верифицировать** — найти свежий артефакт, добавить его в `sources`,
   обновить узел.
2. **Понизить ступень** — если подтверждения нет, уверенность падает честно.

Недопустимый третий: продлить дату без проверки. Это подделка свежести, и
именно она превращает память в документацию, которая выглядит актуальной.

## Что делать с ростом

Память растёт не количеством узлов, а долей решений, которые на неё опираются.
Если за квартал число узлов выросло вдвое, а ответы на вопросы по-прежнему
начинаются с «память не знает» — растёт справочник, а не память. Заводите узел
тогда, когда из-за его отсутствия уже приняли плохое решение.
