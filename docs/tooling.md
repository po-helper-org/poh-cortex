# Инструмент: bin/cortex

Один файл, стандартная библиотека Python, ноль внешних зависимостей. Ставить
нечего, поднимать нечего, форк движка ничему не мешает.

Markdown в git — носитель истины. Индекс и граф строятся в памяти при каждом
запуске (полтысячи узлов ≈ 0.4 c) и **не хранятся**: производный артефакт не
бывает истиной, а хранимый индекс неизбежно расходится с файлами.

## Команды

| Команда | Что делает | Пишет в vault |
|---|---|---|
| `doctor` | что загружено, какой схемой проверяется, чего не хватает | нет |
| `gate` | проверка памяти по схеме; `--all`, `--json` | нет |
| `refresh` | пересчёт `ripeness` и `effective_cp`; `--dry-run` | **да** |
| `report` | узлы, зоны, средняя ступень, увядание, спелость; `--json` | нет |
| `ask "<тема>"` | что память знает, с якорями; `--scope`, `--nexus`, `--json` | нет |
| `context` | `--node` / `--kr` / `--scope`, JSON для агента | нет |
| `who "<тема>"` | кому писать: владельцы релевантных узлов | нет |
| `stale` | очередь верификации протухшего; `--soon` | нет |
| `gaps` | знание, не достижимое от хребта целей | нет |
| `agents` | агенты, их зоны записи и что кто записал | нет |
| `intake list\|route` | очередь неразобранного и куда оно ложится | нет |
| `node new\|set\|check` | контракт записи; всегда сначала `--dry-run` | **да** |
| `nexus list\|add` | объекты управления | **да** |
| `schema show\|init` | схема памяти: показать или сделать своей | **да** |
| `init` | привязать vault к организации | **да** |

Работа с чужим vault: `bin/cortex --root /путь/к/vault <команда>` или
переменная `CORTEX_ROOT`.

## Схема как данные

`GROUND/SCHEMA/` — не конфигурация инструмента, а модель памяти:

| Файл | Что задаёт |
|---|---|
| `nodes.yaml` | обязательные ключи, enum-значения, каталог типов узлов, требования по слою |
| `edges.yaml` | какое поле frontmatter даёт какое ребро и между чем |
| `profiles.yaml` | `change_rate` → срок годности; скорость распада уверенности |
| `ladder.yaml` | лестница доказательств 2–9, потолки канала и полномочий, правила |
| `agents.yaml` | классы агентов, их зоны записи, что не делегируется никому |
| `gate.yaml` | жёсткость каждой проверки: `error` · `warn` · `off` |

Инструмент читает их при каждом запуске. **Новый тип узла, новый объект
управления, новый агент — это декларация, а не правка кода и не PR в чужой
репозиторий.** Отсюда следует совместимость: Кортекс работает на уже наполненном
vault, а если в нём нет своей схемы — берёт ту, с которой поставлен.

## Как считается уверенность

```
cp              ступень 2..9, считанная с лестницы по сильнейшему артефакту
confidence      то же число в долях: cp / 9 — для совместимости и отчётов
effective_cp    cp − распад(время × change_rate)
```

Распад: `p = (сегодня − updated) / ttl_days`. При `p < 0.5` узел свежий,
`< 1.0` созревающий, `≥ 1.0` увядающий. За каждый просроченный срок годности
узел теряет `decay.steps_per_ttl` ступеней, но не ниже `decay.floor`.

Смысл в том, что **протухшее знание теряет уверенность само**, без ручного
прохода по памяти. Продлить дату без проверки источника нельзя — это подделка
свежести, и гейт показывает такой дрейф отдельно.

## Поиск без графовой БД

`ask` строит частотный индекс по заголовкам, тегам и телу узлов, ранжирует
по совпадению и корректирует вес: уверенное знание выигрывает у слухов,
протухшее уступает свежему. `context` обходит рёбра из `edges.yaml` в обе
стороны на заданную глубину.

Этого достаточно для памяти масштаба организации. Векторный поиск и граф-стор
— оптимизация, которая имеет смысл на порядок большем объёме; принимать ради
неё зависимость от сервиса на старте не нужно.
