# Студия Кортекса: `bin/cortex serve`

Визуальный сервис памяти для людей. Тот же vault, тот же инструмент, ставить нечего:

```sh
bin/cortex serve                 # http://127.0.0.1:8765/ — только этот компьютер, запись разрешена
```

Агент работает с памятью командами, человек в Студии. Обе стороны видят одни и те же
файлы и одни и те же расчёты: страница читает память кодом `bin/cortex`, а пишет только
через `bin/cortex`.

## Что в ней

| Раздел | Что видно | Что можно сделать |
|---|---|---|
| **Книга** | главы-Нексусы с числом узлов и зрелостью онбординга, «Решения и ставки», недавнее, протухшее, алерты здоровья | открыть главу, узел, искать |
| **Узел** | шапка, текст, «на чём держится» (источники), связи и обратные связи по полям-рёбрам, находки гейта | — |
| **Поиск** | тот же индекс, что `cortex ask`: уверенное знание выше слухов, протухшее ниже | — |
| **Разбор** | очередь `GROUND/_intake/` с потолком CP по каждой записи, черновики агентов (`status: draft`), строки `inbox.md` | принять запись в узел, отклонить, принять или отклонить черновик |
| **Журнал** | изменения `GROUND/` по дням из git: кто, что и зачем | перейти к узлу |
| **Здоровье** | `cortex health`: гейт, очередь, черновики, протухшее, конфликты, сироты, срезы | — |

## Разбор очереди: как запись становится знанием

Студия закрывает разрыв, на котором стоит большинство памятей: сборщики (боты, агенты,
рефлексии встреч) кладут кандидатов в `_intake/`, а до узлов они не доходят, потому что
разбирать их в терминале долго.

«Принять» по записи очереди делает следующее:

1. Узел создаётся командой `cortex node new --by human --status accepted`, со всеми её
   отказами: нет источника, тип не объявлен, похожий узел уже есть.
2. В источники попадают ссылка записи (`link`) и `intake:<путь>#<хэш>`. В шапку узла
   переносится провенанс: `channel`, `author`, `authority`, `link`, `intake_by`.
3. Если гейт дал ERROR на новом узле, узел удаляется, а запись возвращается в очередь.
4. В `GROUND/DECIDE/log/<ГГГГ-ММ>.md` пишется строка разбора с хэшем записи: по нему
   разобранное не вернётся.
5. Запись очереди удаляется.

«Отклонить» пишет строку журнала с причиной и удаляет запись.

**Потолок CP** берётся из `GROUND/SCHEMA/ladder.yaml`, форма не даёт выбрать выше:

- канал записи — `ceilings.channel` (устное и чат 3, письмо и тикет без потолка); у канала
  без правила потолок 3;
- пересказ сборщика (`captured_by` не `human`, а `authority` пуст или не совпадает с
  `author`) — не выше `ceilings.authority.not_owner` (2);
- выше потолка можно, только если вы добавили **свой** источник-артефакт (документ,
  тикет, письмо), отличный от ссылки записи. Ступень растёт от артефакта, а не от
  рассуждения.

Формат записи очереди описан в `GROUND/_intake/README.md`. Студия дополнительно понимает
подсказки сборщика `title`, `nexus_hint`, `type_hint` и `scope_hint`: ими заполняется
форма приёмки.

## Режимы запуска

| Как | Кто пишет |
|---|---|
| `bin/cortex serve` | любой, кто открыл страницу на этом компьютере (слушает только 127.0.0.1) |
| `bin/cortex serve --read-only` | никто: витрина памяти |
| `bin/cortex serve --host 0.0.0.0 --owners anna,ivan --user-header X-Forwarded-User` | только перечисленные; имя даёт прокси с входом |

Студия не хранит паролей и не делает вход сама. Вне localhost она запускается только с
`--read-only` или с `--owners` и `--user-header`: имя человека подставляет прокси перед
ней (oauth2-proxy, Authentik, nginx `auth_request`). Подделать заголовок нельзя, если до
Студии можно дойти только через прокси. Поэтому держите её на 127.0.0.1 за прокси, а
`--host 0.0.0.0` используйте только в закрытой сети.

Каждый запрос записи требует заголовок `X-Cortex-Studio: 1`, поэтому форма с чужого
сайта ничего не изменит.

Остальные флаги:

- `--commit` — каждое решение уходит отдельным коммитом, и в него попадают **только
  затронутые файлы**: узел, строка журнала и удалённая запись. Посторонний файл в рабочей
  копии (например, оставленный агентом) в память молча не уедет. Отправка коммитов
  (`git push`) остаётся вашей: Студия в удалённый репозиторий не ходит.
- `--base /cortex` — префикс адреса, если Студия стоит за прокси не в корне.
- `--port` — порт, по умолчанию 8765.
- Переменные `CORTEX_STUDIO_OWNERS` и `CORTEX_STUDIO_USER_HEADER` заменяют флаги.

## Постоянный сервис

systemd, пользовательский юнит `~/.config/systemd/user/cortex-studio.service`:

```ini
[Unit]
Description=Студия Кортекса

[Service]
ExecStart=/usr/bin/python3 %h/my-cortex/bin/cortex --root %h/my-cortex serve --port 8765 --commit --base /cortex --owners anna --user-header X-Forwarded-User
Restart=on-failure

[Install]
WantedBy=default.target
```

nginx за входом. Пример для `auth_request` с прокси, отдающим имя в `X-Auth-Request-User`:

```nginx
location /cortex/ {
    auth_request /oauth2/auth;
    auth_request_set $user $upstream_http_x_auth_request_user;
    proxy_set_header X-Forwarded-User $user;
    proxy_pass http://127.0.0.1:8765;
}
```

## API

JSON, для своих интеграций. Чтение — `GET`, запись — `POST` с заголовком `X-Cortex-Studio: 1`.

```
GET  /api/overview                книга: организация, главы, недавнее, протухшее, здоровье
GET  /api/chapter?slug=           глава (slug=decide — слой решений)
GET  /api/node?id=                узел: шапка, текст, связи, обратные связи, находки гейта
GET  /api/search?q=               поиск
GET  /api/queue                   очередь, черновики, inbox.md и схема для формы приёмки
GET  /api/journal?days=30         изменения по дням
GET  /api/health                  то же, что cortex health --json
GET  /api/me                      кто смотрит и может ли писать
POST /api/queue/<id>/accept       {nexus, type, title, scope, cp, change_rate, owner?, sources?, body?, id?, force?}
POST /api/queue/<id>/reject       {reason?}
POST /api/drafts/<node_id>/accept|reject
```

`<id>` записи очереди — хэш её пути (`/api/queue` отдаёт его в поле `id`): сам путь в
адрес не попадает. Ошибки приходят в виде `{ok: false, error, message, field?}`. Важные
коды: `ceiling` (422, CP выше потолка), `duplicate` (422, похожий узел уже есть; повторите
с `force: true`, если это другой объект), `gate` (422, гейт отклонил узел), `read_only`
(403).

## Чего Студия не делает

- Не правит узлы свободным текстом. Изменение узла остаётся за `cortex node set` или
  правкой файла с проверкой `cortex gate`: свежесть и ступень нельзя «продлить» кнопкой.
- Не меняет схему (`GROUND/SCHEMA/`). Правила меняет человек на калибровке, в истории
  репозитория.
- Не принимает в `GROUND/DECIDE/` ставки и доказательства из очереди: у них свои шаблоны и
  обязательные поля (гейт, срок, дата артефакта). Их заводит навык `cortex-bet`.
