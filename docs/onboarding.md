# Заполнение Кортекса: от пустого шаблона до рабочей памяти

Порядок важен: каждый следующий шаг опирается на предыдущий. Пропущенный шаг
превращается в дыру, которую видно в `./scripts/cortex.sh gaps`.

## Шаг 0 — привязать vault к себе

```bash
./scripts/cortex.sh init
```

Заполняет `GROUND/config.yaml` (организация, продукт, slug, идея, продуктовый
инженер), ставит дату создания и выравнивает `updated` во всех узлах на сегодня.

Дальше руками: `team.size`, остальной `roster` (имя человека, `Cortex` для
делегированной роли, `null` если роли нет), `cortex.phase_target`.

**Чек:** `./scripts/cortex.sh gate` → секция ПЛЕЙСХОЛДЕРЫ не упоминает `config.yaml`.

## Шаг 1 — намерение

Заполните `VISION.md`: North Star, модель ценности, beachhead, моат.
Это то, чего нет в графе, но чем граф меряется.

Пустой раздел честнее выдуманного. Если North Star ещё не сформулирован —
так и напишите: онбординг не обязан выдумать за вас стратегию.

> Публичный репозиторий: держите VISION в приватном форке, если там цели,
> оценка актива и потенциальные покупатели.

## Шаг 2 — Нексусы

```
/paf-onboard
```

Порядок: `product` → `customer` → `market` → `growth`, затем `company`, `team`.
По каждому — seed questions из `GROUND/NEXUS/<нексус>/_template.md`.

Правила, которые нельзя ослаблять:

- один факт — один узел;
- `sources` обязателен: документ, интервью, аналитика, решение встречи;
- `confidence` 0.2–0.4, пока нет валидации;
- «не знаю / не мерили» — это результат, а не пробел для заполнения.

**Чек:** `./scripts/cortex.sh report` → Context Ripeness по Нексусам перестала
быть нулевой; `Workslop (без sources)` = число незаполненных `_index`, не больше.

## Шаг 3 — ось ценности

Свяжите узлы полями, а не текстом:

```
segment —has_need→ need ←addresses— value-proposition ←realizes— feature → product
```

**Чек:** `./scripts/cortex.sh gaps` → раздел «Без ценностного ребра» пуст.

## Шаг 4 — хребет OKR

```
/paf-okr
```

Заполните `ROADMAP/kr-epic-map.md`, затем:

```bash
./scripts/cortex.sh build
```

Движок создаст узлы `objective` / `key-result` и запишет рёбра `SERVES` /
`DELIVERS`. Свяжите контент с целями через `satisfies: [kr-1-2]` в узлах.

**Чек:** `./scripts/cortex.sh gaps` → достижимость value-контента от хребта KR
растёт; сироты — это ценность, не привязанная ни к одной цели.

## Шаг 5 — People Graph

Заведите узлы персон (`/paf-node`, Нексус `team`). После этого меняйте `owner:`
в узлах с роли на имя человека: движок сопоставляет первые два токена имени с
`full_name` персоны и выводит ребро OWNS.

**Чек:** в `report` уменьшается очередь «Owner не разрешён».

## Шаг 6 — режим эксплуатации

| Событие | Действие |
|---|---|
| встреча, созвон, ретро | `/paf-pulse` → эпизод в `GROUND/PULSE/summaries/` |
| новый факт, интервью, данные | `/paf-node` → узел или обновление CP |
| узел стал `wilting` | верифицировать источником **или** понизить CP |
| смена квартала | `/paf-okr` → новые Objectives, старые узлы не удалять |
| перед каждым коммитом | `./scripts/cortex.sh gate` |

## Как понять, что память живая

| Признак | Смотреть |
|---|---|
| Context Ripeness ≥ 0.6 по минимальным Нексусам | `report` |
| нет узлов без источника | `gate`, секция workslop |
| нет висячих рёбер | `gate` |
| контент достижим от хребта OKR | `gaps` |
| доля `wilting` не растёт от квартала к кварталу | `gate` |

Обратный признак: узлов много, CP у всех 0.8, источники одинаковые.
Это не зрелая память, это уверенные выдумки.
