# Методология: Нексус, Кортекс, спелость контекста

Кратко о том, на чём стоит этот репозиторий. Первоисточник —
PAF (Product Architecture Framework), [productframework.ru/ops/main][S1],
Тихомиров С., CC BY-SA 4.0.

## Нексус

**Нексус** — живая модель объекта управления: рынка, потребителя, продукта,
системы роста. Не документация *о* объекте, а его цифровой профиль, по которому
принимаются решения.

Реализация здесь: markdown-нота с YAML-frontmatter = **Узел**; поля frontmatter =
**рёбра**; папка `GROUND/NEXUS/<slug>/` = Нексус. Никакой отдельной БД: git
хранит истину, граф и вектор — пересобираемые артефакты.

Минимальный набор PAF — четыре Нексуса:

| Нексус | Объект управления | Роль-владелец |
|---|---|---|
| `product` | продукт: идея, фичи, Видение, гэп | Product Engineer |
| `customer` | потребитель: сегменты, JTBD, боли, mNSM | Product Engineer |
| `market` | рынок: объём, тренды, конкуренты, Ставки | Portfolio Manager |
| `growth` | система роста: каналы, монетизация, рычаги | Growth Engineer |

Опциональные: `ops-model` (правила игры), `company` (портфель), `team`
(People Graph). Дальше — кастомные под ваш объект управления
(`/paf-nexus-create`).

## Кортекс

**Кортекс** — ИИ-операционка, управляющая Нексусами. В этом репозитории Кортекс
это связка: ИИ-агенты (Claude Code, боты профиля Hermes Agent) + контракт
`AGENTS.md` + схема `GROUND/SCHEMA/` + инструмент `bin/cortex`.

Разделение ответственности жёсткое: **система владеет исполнением и формой,
человек владеет целью и решением** (`GROUND/NEXUS/ops-model/delegation-boundary.md`).

## Confidence Point

**CP** — уровень доверия к утверждению, а не к тому, кто его написал. Это
**ступень 2–9**, которая *считывается* с `GROUND/SCHEMA/ladder.yaml` по одному
вопросу: какой самый сильный артефакт существует и открывается по ссылке.
Формулы нет; нет артефакта — нет ступени.

| Ступень | Что за ней стоит |
|---|---|
| 2 | устное: созвон, личные сообщения — от такого можно отказаться |
| 3–4 | письменное или показанное: письмо, тикет с датой, демо |
| 5–6 | проверенное: прогон в искусственных условиях, тест против реальной системы |
| 7–9 | работающее: ограниченный реальный объём, реальная нагрузка, прод |

Три ограничителя, выше которых ступень не поднимается:

| Ограничитель | Правило |
|---|---|
| Scope | «сверка сошлась на 50 транзакциях» — факт про 50, не про 50 000 |
| Authority | повышать CP по объекту может только его владелец; пересказ — слухи |
| Channel | устное и личка — потолок третьей ступени; письмо, тикет, MR — без потолка |

**Правило слабого звена:** CP ставки равен минимуму CP её критических
зависимостей. Цель не прочнее слабейшей ставки.

Правило, ради которого всё затевалось: **CP повышается только новым
источником**. Красивая формулировка, повторное обсуждение и уверенность агента
CP не меняют.

Поле `confidence` (доли) — производное `cp / 9`, оно нужно отчётам и
совместимости. Руками его не ставят.

## Спелость контекста

Метрика качества Нексуса, которую инженер продукта обязан повышать. Складывается
из двух свойств: **полнота** (какая часть структуры заполнена) и **актуальность**
(как давно проверялось). Отсюда два этапа жизни узла — созревание и увядание.

`cortex report` считает спелость Нексуса как произведение двух долей:

```
полнота      = узлов с источниками / всего узлов
актуальность = свежих узлов / всего узлов
спелость     = полнота × актуальность
```

Свежесть самого узла — от срока годности его типа изменений:

```
p = (сегодня − updated) / ttl_days
p < 0.5 → fresh        p < 1.0 → ripening        p ≥ 1.0 → wilting
```

`wilting` — сигнал «проверь или понизь CP», а не «продли дату». Именно увядание
не даёт памяти превратиться в документацию, которая гниёт: протухший узел
автоматически снижает CP всех ставок, которые на нём стоят.

## Ноль галлюцинаций

Узел без `sources` — **workslop**: работа, которая выглядит сделанной и
перекладывает когнитивную нагрузку на следующего читателя. Такой узел в Нексус
не попадает. Онбординг **цифровизует, а не валидирует**: перенос знания в память
не делает его правдой.

## Словарь

| Термин | Смысл |
|---|---|
| Гейт | порог CP плюс дата: при каком уровне даётся обещание наружу. Не путать с `cortex gate` — тот про целостность памяти |
| Стадия (`stage` 1–6) | какой риск ставка снимает сейчас. К календарю не привязана; с гейтом не мапится |
| Банч (Feature Bunch) | связка фич в моменте для закрытия гэпа; заменяет беклог |
| Гэп | разрыв между текущим продуктом и Видением |
| Ставка (Bet) | элемент стратегического сценария; проверяется, а не прогнозируется |
| Рычаг (Lever) | измеримое свойство, дающее рост NPV при инвестиции |
| mNSM | монетизируемая ключевая метрика ценности |
| Скаутинг | поиск возможностей и угроз; заменяет приоритизацию списка задач |
| Workslop | «рабочий мусор»: результат без источника и проверяемости |
| Comb-shaped | широкие компетенции роли за счёт Кортекса |
