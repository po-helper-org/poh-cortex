## Нексус

**Нексус** — живая модель объекта управления: рынка, потребителя, продукта,
системы роста. Не документация *о* объекте, а его цифровой профиль, по которому
принимаются решения.

Реализация здесь: markdown-нота с YAML-frontmatter = **Узел**; поля frontmatter =
**рёбра**; папка `GROUND/NEXUS/<slug>/` = Нексус. Никакой отдельной БД: git
хранит истину, граф и вектор — пересобираемые артефакты.

Минимальный набор PAF — четыре Нексуса:

| Нексус | Объект управления | Роль-владелец |
|---|---|---|
| `product` | продукт: идея, фичи, Видение, гэп | Product Engineer |
| `customer` | потребитель: сегменты, JTBD, боли, mNSM | Product Engineer |
| `market` | рынок: объём, тренды, конкуренты, Ставки | Portfolio Manager |
| `growth` | система роста: каналы, монетизация, рычаги | Growth Engineer |

Опциональные: `ops-model` (правила игры), `company` (портфель), `team`
(People Graph). Дальше — кастомные под ваш объект управления
(`/paf-nexus-create`).

## Кортекс

**Кортекс** — ИИ-операционка, управляющая Нексусами. В этом репозитории Кортекс
это связка: ИИ-агенты (Claude Code, боты профиля Hermes Agent) + контракт
`AGENTS.md` + схема `GROUND/SCHEMA/` + инструмент `bin/cortex`.

Разделение ответственности жёсткое: **система владеет исполнением и формой,
человек владеет целью и решением** (`GROUND/NEXUS/ops-model/delegation-boundary.md`).

## Confidence Point

**CP** — уровень доверия к узлу, а не к тому, кто его написал.

| CP | Основание |
|---|---|
| 0.2–0.4 | допущение онбординга: пересказ документа, мнение, гипотеза |
| 0.5–0.7 | подтверждено интервью или наблюдением |
| 0.8–1.0 | данные, эксперимент; для `normative` — полная трассируемость до источника |

Правило, ради которого всё затевалось: **CP повышается только новым источником**.
Красивая формулировка, повторное обсуждение и уверенность агента CP не меняют.

## Спелость контекста

**Context Ripeness = полнота × актуальность.** Считается по Нексусу:

```
completeness = узлов с заполненными обязательными полями / всего узлов
freshness    = взвешенное по CP среднее от (1 − age/ttl_days)
ContextRipeness = completeness × freshness
```

Порог перехода между шагами PAF — **0.6**. У каждого узла есть срок годности:

```
p = (сегодня − updated) / ttl_days
p < 0.5  → fresh        p < 1.0 → ripening        p ≥ 1.0 → wilting
```

`wilting` — сигнал «проверь или понизь CP», а не «продли дату». Именно wilting
не даёт памяти превратиться в документацию, которая гниёт.

## Ноль галлюцинаций

Узел без `sources` — **workslop**: работа, которая выглядит сделанной и
перекладывает когнитивную нагрузку на следующего читателя. Такой узел в Нексус
не попадает. Онбординг **цифровизует, а не валидирует**: перенос знания в память
не делает его правдой.

## Словарь

| Термин | Смысл |
|---|---|
| Банч (Feature Bunch) | связка фич в моменте для закрытия гэпа; заменяет беклог |
| Гэп | разрыв между текущим продуктом и Видением |
| Ставка (Bet) | элемент стратегического сценария; проверяется, а не прогнозируется |
| Рычаг (Lever) | измеримое свойство, дающее рост NPV при инвестиции |
| mNSM | монетизируемая ключевая метрика ценности |
| Скаутинг | поиск возможностей и угроз; заменяет приоритизацию списка задач |
| Workslop | «рабочий мусор»: результат без источника и проверяемости |
| Comb-shaped | широкие компетенции роли за счёт Кортекса |
