# Миграция наполненного vault на v2

Схема v2 — данные, а не код, поэтому переписывать содержимое узлов не нужно.
Ниже — путь, проверенный на рабочем vault из 506 узлов и 26 Нексусов.

## Сначала посмотреть, ничего не меняя

```sh
bin/cortex --root /путь/к/vault doctor     # что загрузилось и какой схемой проверяется
bin/cortex --root /путь/к/vault gate       # что расходится
```

Если в vault нет `GROUND/SCHEMA/`, инструмент берёт схему, с которой поставлен,
и работает сразу. Ничего не ломается: незнакомые ключи frontmatter он не трогает
и не теряет.

## Три шага

**1. Объявить Нексусы, которые уже живут на диске.** Папка с узлами, которой нет
в реестре, — это дрейф: половина инструментов её видит, половина нет.

```sh
bin/cortex nexus add <slug> --name "<имя>" --scope org --owner "<роль>" \
  --types <тип> --purpose "<зачем>"
```

**2. Объявить типы узлов, которые агенты уже пишут.** В `_registry.yaml` у
Нексуса — `node_types: [...]`. Это и есть точка расширения: тип, который нужен
вашему навыку, объявляется здесь, а не добавляется в код инструмента.

**3. Пересчитать вычисляемые поля.**

```sh
bin/cortex refresh --dry-run    # посмотреть, сколько разошлось
bin/cortex refresh              # пересчитать
```

Коммитить отдельным коммитом: это техническая операция, она не меняет знание,
и смешивать её со смысловыми правками значит терять историю.

## Что получилось на реальном vault

| | до | после |
|---|---|---|
| ошибок гейта | 13 | 0 |
| из них: Нексусы вне реестра | 10 | 0 |
| из них: висячие рёбра | 3 | 0 (ключи трекера объявлены внешними) |
| узлов с дрейфом свежести | 231 | 0 |

Три висячих ребра оказались не ошибкой памяти, а ключами задач трекера в поле
`mentions`. Это объявляется в схеме, а не чинится в содержимом:

```yaml
# GROUND/SCHEMA/edges.yaml
mentions: {edge: MENTIONS, external_pattern: "^task-[A-Z]+-[0-9]+$"}
```

## Что остаётся предупреждениями

`captured_by` у старых узлов пуст — не видно, кто их записал. Это не чинится
задним числом и не должно: провенанс появляется у новых записей. Пока он не
нужен строго, оставьте `missing_provenance: warn` в `config.yaml`.

## Сделать схему своей

```sh
bin/cortex schema init
```

Копирует схему в `GROUND/SCHEMA/` вашего vault. С этого момента лестница,
профили распада, каталог типов и зоны агентов — ваши, и обновление инструмента
их не трогает.
