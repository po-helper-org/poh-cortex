# KR → Epic map

Хребет OKR организации: единственное место, где живут цели квартала.
Движок `paf_index build` читает таблицы ниже и генерирует узлы `objective` /
`key-result` в `GROUND/NEXUS/okr/`, а также рёбра `SERVES` (KR → Objective) и
`DELIVERS` (эпик → KR).

**Пока пуст.** Заполняется командой `/paf-okr` или руками.

## Как заполнять

- Нумерация KR — `<номер Objective>.<номер KR>`: из `2.3` движок выводит,
  что KR служит Objective 2. Порядок строк значения не имеет.
- Колонка «Эпик» — ключ задачи вида `ABC-123` (шаблон `[A-Z]{2,}-\d+`).
  Пустая ячейка означает: эпик ещё не заведён, ребро `DELIVERS` не выводится.
  **Не выдумывать ключи** — движок поверит любому.
- Формулировка KR — измеримый результат, а не действие. «Замерен baseline
  четырёх функций» — да; «поработать над метриками» — нет.
- Baseline, который не измерен, так и пишется: пустой. Правдоподобное число
  вместо измерения — тот же workslop, только в OKR.

Формат строки: `| 1.1 | Медианное время подготовки требований сокращено | ABC-42 |`

> Пример намеренно дан строкой кода, а не строкой таблицы: парсер движка читает
> файл построчно и не знает про блоки кода — любая строка вида `| … | … | … |`
> станет живым KR.
