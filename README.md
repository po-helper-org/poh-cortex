# poh-cortex — Кортекс организации

**Память организации для ИИ-агентов PO.** Markdown в git, один инструмент на
стандартной библиотеке Python, схема, которая расширяется декларацией.
Ни базы, ни сервисов, ни зависимостей.

Не документация о продукте, а цифровой профиль организации: кто мы, для кого,
чем защищены, к каким целям движемся, и **чем каждое утверждение подтверждено**.

## Зачем

Чтобы ИИ-агент принимал управленческие решения не на общих соображениях, а на
памяти организации — с проверяемыми источниками, честной уверенностью и
привязкой к целям квартала. И чтобы **несколько агентов** делали это, не портя
память друг другу: у записи есть зона, у знания — владелец, у уверенности —
линейка, которую нельзя подкрутить на ходу.

## Установка

```sh
git clone https://github.com/po-helper-org/poh-cortex my-cortex
cd my-cortex && bin/cortex doctor
```

Всё. `python3` уже есть в системе, больше ничего не нужно.

## Вход для ИИ-агента

Агент, получивший ссылку на репозиторий, читает **[ONBOARDING.md](ONBOARDING.md)** —
порядок действий без зависимости от конкретного инструмента агента — и
**[AGENTS.md](AGENTS.md)** — контракт памяти.

## QuickStart

```sh
bin/cortex init          привязать vault к организации
bin/cortex schema init   сделать схему своей, чтобы адаптировать под себя
bin/cortex doctor        проверить, что загрузилось
bin/cortex gate          ноль ERROR на чистом клоне
```

Дальше — наполнение. Агент в Claude Code подхватывает `CLAUDE.md` → `AGENTS.md`
и скиллы из `.claude/skills/`:

| Событие | Команда |
|---|---|
| оцифровать контекст организации | `/paf-onboard` |
| новый факт, интервью, данные | `/paf-node` |
| цели квартала | `/paf-okr` |
| встреча, созвон, ретро | `/paf-pulse` |
| новый объект управления | `/paf-nexus-create` |
| гейт красный | `/paf-gate` |
| спросить память | `/cortex-ask` |
| что требует внимания сегодня | `bin/cortex agenda` |
| расхождения между зонами | `bin/cortex conflicts` |
| итоги квартала | `bin/cortex calibrate` |
| обещание с датой | `/cortex-bet` |

## Структура

```
bin/cortex                  инструмент: гейт, поиск, запись, отчёты
GROUND/
  config.yaml               организация, зоны, уровень зрелости, жёсткость гейта
  SCHEMA/                   ← правила памяти как данные
    nodes.yaml              типы узлов и обязательные поля
    edges.yaml              рёбра: какое поле даёт какую связь
    profiles.yaml           распад: change_rate → срок годности
    ladder.yaml             лестница доказательств 2–9 и потолки
    agents.yaml             агенты и зоны записи
  NEXUS/                    знание: узлы с источниками
    _registry.yaml          Нексусы, их зоны и типы узлов
  DECIDE/                   обещания, артефакты, решения, наблюдения
  PULSE/                    операционный след: встречи, радары, дни
  _intake/                  неразобранный поток — сюда пишут сборщики
  _index/packs/             срезы памяти под профили (производное, пересобирается)
ROADMAP/kr-epic-map.md      хребет OKR: KR → эпик
```

## Модель

Каждый `.md` с YAML-frontmatter — **узел**. Поля frontmatter — **рёбра**.

```
segment —has_need→ need ←addresses— value-proposition ←realizes— feature → product
                                                                    ↓ satisfies
                                                                key-result —serves→ objective
```

**Уверенность** — ступень 2–9 из `SCHEMA/ladder.yaml`: считывается по самому
сильному артефакту, который открывается по ссылке. Устное — не выше третьей,
пересказ чужих слов — не выше второй.

**Распад** — `effective_cp = cp − распад(время × change_rate)`. Протухшее знание
теряет ступень само; данных о частоте изменений нет — ставится `high`, не среднее.

## Несколько агентов в одной памяти

| Класс | Кто | Куда пишет |
|---|---|---|
| детерминированный | агент над файлами и git | `NEXUS/`, `DECIDE/` — после подтверждения |
| самообучающийся | боты профиля Hermes Agent | только `_intake/` и `DECIDE/log/` |
| человек | PO | всё, включая правила |

Уверенность считает только детерминированный агент. Самообучающийся меняет свои
навыки по опыту — для рутины это достоинство, для расчёта уверенности дефект.
Зоны объявлены в `SCHEMA/agents.yaml` и проверяются гейтом, а не договорённостью.

Каждый PO — профиль со своей зоной; **зоны пересекаются сознательно**, потому
что связный продукт требует координации. Профиль получает срез памяти
(`cortex pack`), видит свои стыки с другими PO (`cortex seams`) и подписывается
на то чужое, что ему нужно часто.

## Совместимость

Схема — данные, поэтому Кортекс работает и на уже наполненном vault: если в нём
нет `GROUND/SCHEMA/`, инструмент берёт схему, с которой поставлен, и ничего не
ломает. `cortex schema init` делает схему своей, `cortex nexus add` объявляет
существующий каталог, `cortex refresh` приводит вычисляемые поля в порядок.

```sh
bin/cortex --root /путь/к/vault doctor
bin/cortex --root /путь/к/vault gate
```

## Что здесь сознательно пусто

Шаблон не приносит чужую стратегию. Пустые `VISION.md`, Нексусы и хребет OKR —
стартовое состояние: онбординг **цифровизует, а не валидирует**, и правдоподобный
текст вместо вашего контекста был бы workslop с первого дня.

Единственное заполненное — `ops-model`: принципы, граница делегирования,
протокол памяти и контракт агентов. Это методология, она одинакова для всех.
