# Очередь: единственная зона, куда пишут сборщики

Сюда пишут все, кто приносит поток: человек вручную, боты Hermes Agent, шлюз
мессенджеров, выгрузки чатов и транскриптов. Больше никуда они не пишут —
ни в `NEXUS/`, ни в `DECIDE/`. Это проверяется гейтом по полю `captured_by`
и зонам из `GROUND/SCHEMA/agents.yaml`, а не держится на дисциплине.

Причина простая: поток, который сам себя записывает в знание, через месяц
неотличим от знания. Знанием запись становится после разбора человеком.

```
_intake/
  inbox.md        быстрые вставки человека из переписки
  hermes/         выход ботов профиля Hermes Agent
  chats/          выгрузки чатов
  <источник>/     любой новый поставщик — своим каталогом
```

## Формат записи

Три строки. Дайджесты переписки сюда не копируются: копируется цитата.

```
2026-09-17 | Петров, владелец БАЗИС | slack: <permalink>
"объём подтвердим к концу недели, схему отдадим после"
```

Запись покрупнее — файлом с frontmatter, чтобы агент не гадал:

```yaml
---
captured_by: hermes:keeper      # обязателен: видно, кто принёс
date: 2026-09-17
author: Петров
authority: владелец БАЗИС       # если автор не владелец объекта — ступень не выше 2
channel: chat                   # устное и чат — потолок ступени 3
link: <permalink>
about: [bet-settlement-external]
---
```

Зачем permalink, если агент не может его открыть: ссылка нужна не агенту, а
человеку — чтобы через полгода можно было проверить источник. Провенанс требует
локализуемой ссылки, а не машиночитаемой.

## Что дальше

```sh
cortex intake list              что лежит и откуда
cortex intake route <файл>      куда это ложится по текущей памяти — предложение
cortex node new ...             запись; её делает человек или детерминированный агент
```

Разобранные записи удаляются из `inbox.md`. Запись, которая ни к чему не
относится, выбрасывается — это нормальный исход разбора, а не потеря.
