# Контракт агентов: кто считает, кто собирает, кто решает

Три класса агентов работают с этой памятью, и у каждого своя граница.

| Класс | Кто | Сильная сторона | Куда пишет |
|---|---|---|---|
| детерминированный | агент над файлами и git | одни артефакты по одним правилам дают одно число | `NEXUS/`, `DECIDE/` — после подтверждения |
| самообучающийся | боты профиля Hermes Agent | работает постоянно, помнит контекст, учится на повторах | только `_intake/` и `DECIDE/log/` |
| человек | PO | решение, цель, приоритет, обещание | всё, включая правила |

**Уверенность считает только детерминированный агент по `SCHEMA/ladder.yaml`.**
Ценность числа уверенности в том, что его нельзя подкрутить. Агент, который
меняет свои навыки по опыту, через месяц начнёт считать иначе, чем
договорились: для рутины это достоинство, для расчёта уверенности — дефект.

Отсюда разделение: самообучающиеся собирают и готовят, детерминированный
считает, человек подтверждает запись между ними. Зоны объявлены в
`GROUND/SCHEMA/agents.yaml` и проверяются гейтом по полю `captured_by` —
это правило живёт в проверке, а не в договорённости.

## Чего не делегируется никому

Обещания наружу (даты, сроки, объём) · изменение правил (лестница, пороги,
сроки годности) · отправка сообщений от имени человека · переговоры о датах и
ёмкости · запись в узлы без подтверждения.

## Порядок подключения

Первый квартал — только детерминированный агент: правила должны устояться.
Агенты поверх неустоявшейся системы автоматизируют хаос. Боты Hermes
добавляются, когда лестница откалибрована и очередь `_intake/` работает.
