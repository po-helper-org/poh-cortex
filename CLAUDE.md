Ниже только то, что нарушается чаще всего.

@AGENTS.md

## Инструмент

```sh
bin/cortex doctor        что загружено и какой схемой проверяется
bin/cortex ask "<тема>"  что память знает — с якорями
bin/cortex gate          проверка перед коммитом: ноль ERROR
bin/cortex refresh       пересчёт свежести и распада CP
bin/cortex report        узлы, зоны, спелость по Нексусам
bin/cortex node new …    запись узла (всегда сначала --dry-run)
bin/cortex intake list   что лежит неразобранного
bin/cortex who "<тема>"  кому писать по теме
```

Только стандартная библиотека Python. Ставить нечего, поднимать нечего.

## Пять правил, без которых не начинать

1. `sources` обязателен. Узел без источника = workslop, он не создаётся.
2. Уверенность выводится из `GROUND/SCHEMA/ladder.yaml` по артефакту, а не
   назначается. Повышение `cp` без нового источника инструмент отклонит.
3. Рёбра пишутся полями frontmatter, а не упоминанием в тексте.
4. Ссылка на несуществующий `node_id` роняет гейт. Сначала узел, потом ссылка.
5. Перед коммитом — `bin/cortex gate`, ноль ERROR.

## Чего не делать

- Не писать в `GROUND/NEXUS/` и `GROUND/DECIDE/` без подтверждения человека:
  показывайте `--dry-run` и ждите ответа.
- Не заполнять пустой раздел правдоподобным текстом ради полноты.
- Не продлевать `updated`, чтобы убрать увядание: узел либо верифицируют
  источником, либо понижают ему CP.
- Не решать за человека цель, приоритет, обещание наружу и правила.
