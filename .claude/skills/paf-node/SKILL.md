# Узел Нексуса: создать или обновить

## Создать

1. **Нексус.** Значение `nexus:` — только из `GROUND/NEXUS/_registry.yaml`.
   Нужного нет → `/paf-nexus-create`, а не произвольный slug.
2. **Дубликат?** `./scripts/cortex.sh report` или поиск по `node_id`.
   Обновить существующий узел лучше, чем завести второй про то же.
3. **Шаблон.** `GROUND/NEXUS/<нексус>/_template.md` — скопируйте блок frontmatter.
4. **`node_id`.** ascii, нижний регистр, стабильный навсегда. Префиксы по смыслу:
   `seg-` сегмент, `need-` потребность, `vp-` ценностное предложение,
   `f-` фича, `team-` персона, `bet-` Ставка.
5. **`sources`.** Обязателен и конкретен: `["interview:CPO 2026-02-11"]`,
   `["analytics:cohort-q1"]`, `["doc:стратегия-2026.pdf"]`.
   Источника нет — узел не создаётся.
6. **`confidence`.** 0.2–0.4 допущение · 0.5–0.7 интервью · 0.8–1.0 данные.
7. **Рёбра.** Только на существующие `node_id`. Ось ценности:
   `segment —has_need→ need ←addresses— value-proposition ←realizes— feature → product`.
8. **Тело.** 3–8 строк. Допущение помечается:
   `> ⚠️ допущение (онбординг), требует валидации в Steps 1–8.`
9. `./scripts/cortex.sh gate`.

## Обновить

- Поменяли смысл → `updated` = сегодня.
- Повышаете `confidence` → **добавьте новый источник в `sources`**.
  Без нового источника CP не меняется. Это не формальность: CP — единственная
  защита памяти от накопления уверенных выдумок.
- Узел `wilting` → верифицируйте источником или понизьте CP. Не продлевайте
  дату «чтобы стало зелёно».
- Противоречие → сохраните оба источника и опишите в теле, что изменилось.

## Не делать

- Не править файлы в `GROUND/NEXUS/okr/` и `GROUND/NEXUS/pulse/` — их пишет движок.
- Не менять `node_id` существующего узла: это разрывает все рёбра на него.
- Не ставить `ripeness` руками в противоречие с `updated` + `ttl_days` —
  гейт поймает дрейф.
