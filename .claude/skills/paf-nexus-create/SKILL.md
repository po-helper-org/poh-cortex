# Создать кастомный Нексус

PAF даёт минимум из четырёх Нексусов (`product`, `customer`, `market`, `growth`)
плюс опциональные (`ops-model`, `company`, `team`). Всё остальное — под объект
управления конкретной организации.

## Когда это оправдано

Заводите Нексус, если у организации есть **объект управления**, о котором
регулярно принимаются решения и который не влезает в существующие: продавцы,
партнёрская сеть, поставщики, регуляторика, инфраструктура.

Не заводите Нексус ради одного узла — положите его в ближайший существующий.

## Процедура

1. Спросите человека: `name`, `slug`, `purpose`, владелец (роль или имя из
   `team.roster`), 3–5 seed questions.
2. `slug`: `[a-z][a-z0-9-]*`, уникален, не конфликтует с существующими.
3. Создайте `GROUND/NEXUS/<slug>/`:
   - `_index.md` — MOC-заглушка (`node_type: spine`, `sources: []` допустимо
     до онбординга) с таблицей «какие узлы здесь должны появиться»;
   - `_template.md` — шаблон узла с fenced-блоком frontmatter и seed questions.
     **Реальный frontmatter в `_template.md` не ставить**: инструмент читает
     любой файл с frontmatter и создаст узел-фантом.
4. Объявите в реестре — одной командой:
   `bin/cortex nexus add <slug> --name "<имя>" --scope org --owner "<роль>" --types <тип> --purpose "<зачем>"`

   В объявлении важны два поля, которых раньше не было:
   - `scope` — чей это объект: `org` (общий на организацию), `team:<имя>`,
     `product:<имя>`. Общие объекты (IT-ландшафт, орг.структура, операционная
     модель) — `org`; стратегия и эксперименты — по команде.
   - `node_types` — какие типы узлов здесь допустимы. **Схема расширяется
     здесь**, а не в коде инструмента: нужен свой тип — объявите его.
6. `bin/cortex gate` — узлы с новым `nexus:` теперь проходят проверку.
7. Наполните: `/paf-onboard` по seed questions нового Нексуса.

## Расширение схемы

Если типу нужны свои поля (например `quota_attainment` у продавцов) — опишите
их в `_template.md` как `schema_extensions`. Базовые ключи Node schema они
не заменяют: `sources`, `confidence`, `updated`, `ttl_days`, `ripeness`
обязательны и здесь.
